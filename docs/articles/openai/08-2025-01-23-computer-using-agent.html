Computer-Using Agent：计算机使用智能体

为 Operator 提供动力的 Computer-Using Agent，是 AI 与数字世界交互的通用接口。

今天我们发布了 Operator 的研究预览，一个可以到网络上为你执行任务的智能体。为 Operator 提供动力的是 Computer-Using Agent（CUA），它把 GPT-4o 的视觉能力与通过强化学习获得的高级推理结合起来。CUA 被训练为像人一样与图形用户界面（GUI）——屏幕上的按钮、菜单和文本框——交互。这使它能在不使用操作系统或网站专用 API 的情况下，灵活完成数字任务。

CUA 建立在多年处于多模态理解与推理交叉点的基础研究之上。通过把先进的 GUI 感知与结构化问题解决结合起来，它可以把任务拆成多步计划，并在出现挑战时自适应地自我纠正。这一能力标志着 AI 发展的下一步：让模型使用人类日常依赖的同一套工具，并打开广泛的新应用大门。

尽管 CUA 仍处于早期并有局限，它在基准上刷新了领先结果：在 OSWorld 的完整计算机使用任务上成功率为 38.1%，在 WebArena 上为 58.1%，在 WebVoyager 的基于网页任务上为 87%。这些结果凸显了 CUA 使用单一通用动作空间，在多样环境中导航和操作的能力。

我们把安全放在首位来开发 CUA，以应对智能体访问数字世界所带来的挑战，详见 Operator System Card。遵循迭代部署策略，我们首先通过 operator.chatgpt.com 上的 Operator 研究预览，向美国的 Pro 层级用户发布 CUA。通过收集真实世界反馈，我们可以完善安全措施并持续改进，为数字智能体日益增多的未来做准备。

它如何工作

CUA 处理原始像素数据以理解屏幕上发生的事，并使用虚拟鼠标和键盘完成动作。它可以导航多步任务、处理错误，并适应意外变化。这使 CUA 能在广泛的数字环境中行动，完成填写表单和浏览网站等任务，而无需专用 API。

给定用户指令，CUA 通过一个整合感知、推理和动作的迭代循环运转：

  • 感知：来自计算机的截图被加入模型的上下文，提供计算机当前状态的视觉快照。
  • 推理：CUA 使用思维链推理下一步，同时考虑当前和过去的截图与动作。这种内部独白通过让模型评估观察、跟踪中间步骤并动态适应，来提高任务表现。
  • 动作：它执行点击、滚动或输入等动作，直到判定任务完成或需要用户输入。虽然大多数步骤自动处理，但 CUA 会为敏感动作（例如输入登录信息或响应 CAPTCHA）寻求用户确认。

浏览器使用

WebArena 和 WebVoyager 用于评估网页浏览智能体在用浏览器完成真实任务时的表现。WebArena 使用自托管的开源网站离线模仿电商、CMS、社交论坛等真实场景。WebVoyager 在 Amazon、GitHub、Google Maps 等在线实时网站上测试模型。

在这些基准上，CUA 使用同一通用接口——把浏览器屏幕视为像素，并通过鼠标和键盘采取动作——树立了新标准。CUA 在 WebArena 上达到 58.1%，在 WebVoyager 上达到 87%。虽然在任务相对简单的 WebVoyager 上成功率很高，但在更复杂的 WebArena 上，CUA 仍需更多改进才能缩小与人类表现的差距。

计算机使用

OSWorld 评估模型控制 Ubuntu、Windows 和 macOS 等完整操作系统的能力。在该基准上，CUA 达到 38.1% 的成功率。我们观察到 test-time scaling，即允许更多步骤时 CUA 的表现会提高。人类在该基准上的表现为 72.4%，因此仍有显著提升空间。原文可视化展示了 CUA 完成多种标准化 OSWorld 任务的例子。

Operator 中的 CUA

我们通过 Operator 的研究预览提供 CUA。Operator 是一个可以到网络上为你执行任务的智能体，向美国的 Pro 用户在 operator.chatgpt.com 提供。这一研究预览是向用户和更广泛生态学习、迭代改进 Operator 的机会。与任何早期技术一样，我们并不期望 CUA 在所有场景中都可靠。不过它已在多种情况下被证明有用，我们的目标是把这种可靠性扩展到更广泛的任务。通过在 Operator 中发布 CUA，我们希望收集宝贵洞察，指导我们完善其能力并扩展应用。

原文表格给出了在 Operator 中若干提示的尝试成功率，用以说明已知的优势与弱点：与各种 UI 组件交互以完成任务时，可靠性因网站和 UI 而异；对可通过重复简单 UI 交互完成的任务（如创建购物清单或歌单）成功率很高；当提示包含关于如何使用网站的详细提示时成功率会明显提高；在不熟悉的 UI 和精确文本编辑上仍然吃力，常常需要大量试错，也容易在编辑中出错。完整提示、轨迹与分数请见原文。

安全

因为 CUA 是我们首批能在浏览器中直接采取动作的智能体产品之一，它带来了新的风险与需要应对的挑战。在准备部署 Operator 时，我们做了广泛的安全测试，并在三类主要安全风险上实施了缓解：滥用、模型错误，以及前沿风险。我们相信采取分层安全方法很重要，因此在整个部署上下文中实施了防护：CUA 模型本身、Operator 系统，以及部署后流程。目标是让缓解措施叠加，每一层都逐步降低风险状况。

第一类风险是滥用。除要求用户遵守使用政策外，我们设计了以下缓解以降低 Operator 因滥用造成伤害的风险，并建立在我们对 GPT-4o 的安全工作之上：

  • 拒绝：CUA 模型被训练为拒绝许多有害任务以及非法或受监管的活动。
  • 屏蔽名单：Operator 不能访问我们预先屏蔽的网站，例如许多赌博站点、成人娱乐，以及毒品或枪支零售商。
  • 审核：用户交互由自动安全检查器实时审查，旨在确保符合使用政策，并有能力对禁止活动发出警告或阻止。
  • 离线检测：我们还开发了自动检测与人工审查流水线，以识别包括儿童安全与欺骗活动在内的优先政策领域中的禁止使用，从而执行使用政策。

第二类风险是模型错误，即 CUA 模型意外采取了用户并未打算的动作，进而对用户或其他人造成伤害。假设中的错误严重程度可以从邮件中的错字，到购买错误商品，再到永久删除重要文档。为尽量减少潜在伤害，我们开发了以下缓解：

  • 用户确认：CUA 模型被训练为在完成具有外部副作用的任务（例如提交订单、发送邮件等）之前征求用户确认，以便用户在结果永久化之前复核模型的工作。
  • 任务限制：目前，CUA 模型会拒绝帮助某些更高风险的任务，例如银行交易以及需要敏感决策的任务。
  • 监视模式（Watch mode）：在电子邮件等特别敏感的网站上，Operator 要求用户进行主动监督，确保用户可以直接发现并处理模型可能犯的任何错误。

一类特别重要的模型错误，是网站上的对抗攻击通过提示注入、jailbreak 和钓鱼尝试，导致 CUA 模型采取非预期动作。除上述针对模型错误的缓解外，我们还开发了若干额外防御层：

  • 谨慎导航：CUA 模型被设计为识别并忽略网站上的提示注入，在一次早期内部红队演练中识别了除一例之外的所有情况。
  • 监控：在 Operator 中，我们实现了额外的模型来监控，并在检测到屏幕上的可疑内容时暂停执行。
  • 检测流水线：我们同时应用自动检测和人工审查流水线，以识别可被标记并迅速加入监控的可疑访问模式（可在数小时内完成）。

最后，我们对照 Preparedness Framework 中概述的前沿风险评估了 CUA 模型，包括涉及自主复制和生物风险工具的场景。这些评估显示，在 GPT-4o 之上没有增量风险。

对评估与防护的更详细探讨，请参阅 Operator System Card 这一持续更新的文档，它提供了我们安全方法与持续改进的透明度。

由于 Operator 的许多能力是新的，我们所实施的风险与缓解方法也是新的。虽然我们力求达到先进、多样且互补的缓解，但我们预期这些风险和我们的方法会随着学习而演化。我们期待把研究预览期用作收集用户反馈、完善防护并增强智能体安全的机会。

结语

CUA 建立在多模态、推理和安全方面多年的研究进展之上。我们通过 o 系列模型在深度推理上取得了显著进展，通过 GPT-4o 提升了视觉能力，并通过强化学习和指令层级等新技术提高了稳健性。我们计划探索的下一个挑战空间，是扩展智能体的动作空间。通用接口所提供的灵活性应对了这一挑战，使智能体能够导航为人设计的任何软件工具。通过超越专用的、对智能体友好的 API，CUA 可以适应无论怎样的计算机环境——真正覆盖大多数 AI 模型仍无法触及的数字用例「长尾」。

我们也在努力把 CUA 放入 API，以便开发者用它构建自己的计算机使用智能体。在继续迭代 CUA 的过程中，我们期待看到社区发现的不同用例。我们计划利用这次早期预览收集的真实世界反馈，持续完善 CUA 的能力与安全缓解，从而安全地推进把 AI 的益处分给每一个人的使命。
