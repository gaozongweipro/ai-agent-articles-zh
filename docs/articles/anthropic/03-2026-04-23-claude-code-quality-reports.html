Claude Code评测质量

关于近期 Claude Code 质量报告的更新

用户报告 Claude Code 质量出现不一致下降。事后分析表明，这不是单一回归，而是三项在不同流量切片、不同时间线上生效的改动叠加，看起来像广泛而不稳定的退化：

  1. 2 月在 Claude Code 中发布 Opus 4.6 时，默认 reasoning effort 被设为 high。部分用户反馈模型思考过久，UI 像卡住，延迟和 token 消耗过高，随后对默认 effort 做了校准调整。
  2. 一项缓存优化丢弃了先前的 reasoning（prior reasoning），影响了后续质量。
  3. 4 月 16 日加入一条减少啰嗦的 system prompt 指令，与其他 prompt 改动组合后损害了编程质量，于 4 月 20 日回滚。影响了 Sonnet 4.6、Opus 4.6 和 Opus 4.7。

团队从 3 月初开始调查报告，但起初难以与正常用户反馈波动区分，内部使用和 evals 起初也未能复现。问题已在 4 月 20 日的 v2.1.116 中解决。截至 4 月 23 日，Anthropic 为所有订阅用户重置了用量限制。
